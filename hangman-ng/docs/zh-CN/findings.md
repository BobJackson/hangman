# 测量说明了什么

[English](../findings.md) | 中文

一页。这里每个数字背后的证据、以及如何复现它，在[本目录的 README](README.md)里；设计背后的推理在
[设计文档](specs/2026-10-22-hangman-redesign-design.md)里。

## 头条

每局平均 **1404.65** 分（sd 34.75，100 局，种子 42，80 词，加权答案，bucketed 档位）。一个早已
知道所有答案、从不失手的玩家会拿到 **1600**。

所以缺口是 **195 分**，而这一页讲的就是这里面装了什么。

## 每项改动值多少

| 改动 | 每局分数 | 怎么测的 |
|---|---:|---|
| 相对原客户端重写 | **+144** | 同一个模拟器、同一个种子、同一套规则 |
| 用语料先验取代均匀先验 | **+119** | 全项目任意单项中最大的效果 |
| 从 8 次提交里取最好 | **+48** | 一条服务器规则，不是算法；采用它不花分数 |
| 放弃词，带先知先觉 | **+10** | 而没有先知先觉时恰好是 0 —— 测了两次 |
| 精确前瞻，仅终局 | **+1.3 到 +3.1** | 1.6% 到 3.7% 的决策被精确定价 |
| 最大化信息量而不是命中 | **−875** | 错的目标，被测过而不是被争论 |
| 用每次猜测自己的赔率给它定价 | **0** | 没有可修的；见下 |

表里有两件事值得注意。最大的收益来自一个规则问题，而不是求解器。而造出来的两样最精巧的东西 ——
信息增益和精确前瞻 —— 分别值 −875 和 +3。

## 两个负面结果

**M5 —— 终局已经接近最优。** `ExactScore` 把一个决策完整求解出来，所以它的答案是真实期望，而不是
估计。在能算完的那些状态上，`coverage` 的选择有 9% 到 21% 不是最优，而这一切总共每局值 1.26 到
3.14 分 —— 每次错误决策 0.12 分。在一个词接近结束时，期望在几个合理字母之间几乎是平的：只剩一次
失手、三个候选词时，确定揭示和一个三分之一的命中都值 `20/3`。把范围放宽 2.3 倍买到 1.9 分，墙上
时间翻倍。

**M6 —— 每一次失手都被定价了，而且价格是对的。** 审计只够到 1.6% 的决策，所以第二个探针包住求解器
并记录全部 70,788 次，每一次都对照促使它发生的那个 `P(hit)`。一半的猜测（49.2%）落在每个幸存候选词
都含有的字母上 —— 必然命中，它们只贡献 0.9% 的失手。另一半以 42.7% 失手，而模型预测约 43%。在十个
`P(hit)` 十分位、十八种词长和十个猜测序号上逐行看，除了一行 53 个决策的之外，最大偏差是一个标准误。

单靠校准只能说明模型知道自己的赔率。它之所以变得有决定性，是因为叠加了 `coverage` 每一步都在最大化
同一个数这一事实：没有别的字母能在它被选中的那一刻降低期望失手数。

## 195 分在哪里

| 档位 | 每局失手 | 每局未解词 | 分 |
|---|---:|---:|---:|
| 1-20（3-5） | 92.6 | 2.01 | **132.8** |
| 21-40（6-8） | 43.6 | 0.01 | 43.8 |
| 41-60（9-12） | 15.0 | 0 | 15.0 |
| 61-80（13+） | 4.0 | 0 | 4.0 |

其中三分之二是短词档，而原因是算术，不是策略。一个三字母答案只有三个位置放一个字母，而可用的最好
字母只出现在 28.6% 的幸存词里；一个十三字母答案有十三个位置，最好的字母出现在其中 97.6%。这就是
为什么三字母词有 71.4% 的时间在失手，而十三字母只有 2.4%。

所以缺口分解为大约 155 分的失手，和 40 分的从未解出的词 —— 8,000 个里的 202 个，几乎全在第一档。
两者都不是靠选更好的字母能拿到的：选出的字母已经是可用的最好的，而它们产生的失手按上面引的比率
到达。

## 要拿到剩下的，什么必须成立

剩下的唯一杠杆是**序列**：现在吃一个更差的字母，换接下来三次更好的赔率。这件事两端都测过，中间
没有。

- 在极端一端，`information` 用失手去买信息，输掉 875 分。这里探索不免费：分数每回合变化 `21p − 1`，
  对 `p` 单调。
- 在终局，精确定价说最好的序列值 1.3 到 3.1 分。
- 在中间 —— 一千个候选词，大部分失手还在手里 —— 每个决策的状态空间约为 `2^15`，每个要 26 次字母
  评估。这里没有任何东西给它定价。

因此，说中间值 100 分是没有依据的，说它一文不值同样没有依据。能说的是更窄也更确定的东西：**每一步
选出的字母都是可用的最好的那个，而它产生的失手是它许诺的那些。** 任何剩余改进都必须来自一个还不
存在的规划器，而不是来自修正当前这个的错误。

## 复现

```bash
cd hangman-ng
mvn test                                     # 172 tests, no network, no sleeps
mvn -q package
java -jar target/hangman-ng.jar --variants coverage,legacy,information
java -jar target/hangman-ng.jar --variants coverage,audited
java -jar target/hangman-ng.jar --variants coverage,anatomy
```

三次运行都用 `--games 100 --seed 42`，而默认不是；README 在它报告的每张表旁边都印出了确切的参数。
