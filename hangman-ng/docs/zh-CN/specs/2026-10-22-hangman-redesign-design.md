# hangman-ng —— 设计

[English](../../specs/2026-10-22-hangman-redesign-design.md) | 中文

日期：2026-10-22
状态：M1-M6 已实现并测量

## 目标

把 Strikingly 的 Hangman 面试题实现成这样一种东西：策略可以**被经验地比较**，而不是被争论。交付物
是一个求解器，以及用来评判它的仪器：可复现的离线模拟器、评测 harness、按难度档位分列的报告。

仓库里已经有一个 Java 8 实现（`HangmanPlayer.java`，579 行），2017 年在真实服务器上拿到过 1326 分。
那个实现保持原样，作为下面每一次比较的参照点。

## 约束

- Java 21（LTS）、Maven、JUnit 5 + AssertJ。
- 新模块 `hangman-ng`；不修改、不删除任何已有文件。
- 无运行时依赖，M4 也一样。`java.net.http` 在 JDK 里，而协议的 JSON 小到一个 240 行的递归下降
  解析器就胜过 2018 年出品的 Jackson —— 那是这里离线唯一能拿到的版本。
- 允许下载外部词频数据；产物以 gzip 资源的形式提交，这样构建保持离线且可复现。

## 计分模型

说明里从没写出公式。它可以从公布的两个样例反推：

| 正确词数 | 失手数 | 公布的分数 | `20 * correct - wrong` |
|---:|---:|---:|---:|
| 78 | 234 | 1326 | 1326 |
| 77 | 233 | 1307 | 1307 |

`score = 20 * correctWordCount - totalWrongGuessCount`。编码在 `GameResult.scoreOf` 里，并由
`isScoreConsistent()` 在运行时断言。

对策略的推论：只要 `p(hit) * 20` 超过它可能造成的失手的期望代价，这次猜测就值得做。因此最大化
P(hit) —— 旧实现也在用的贪心规则 —— 是正确的第一阶目标。四个替代方案是被构建并被测量、而不是被
争论的，四个全都偏小或为负：信息增益目标差 875 分；放弃词的收益被它自己吃掉（最好的版本值十分）；
对可定价决策做精确前瞻，每局值 1.3 到 3.1 分；逐次探针则发现失手恰好按模型分配的概率到达。

## 模块设计

```
api        HangmanClient, StartGame, WordState, GameResult, HangmanApiException
dict       Dictionary, DictionaryLoader, WordWeighting, RankWordWeighting
solver     Solver, EliminationSolver, LetterSelector, FrequencyLetterSelector,
           InformationGainLetterSelector, SkipPolicy, SkipContext, GuessContext,
           ExactScore, AuditedLetterSelector, AuditSummary,
           MissAnatomy, MissAnatomySummary
engine     GameEngine, GameListener
sim        SimulatedServer, SimulationConfig, EvaluationHarness, BenchmarkReport
transport  HttpHangmanClient, Json, RetryingHangmanClient, Sleeper
cli        GameRunner
```

依赖方向：`cli → sim → engine → solver → dict → api`。没有环；`solver` 完全不知道 HTTP、计分或
游戏流程；`engine` 不持有任何按词的状态。

### 不变量

1. **一个词，一个求解器。** `Solver` 由 `SolverFactory` 按词创建并丢弃。所有按词的状态（已猜掩码、
   模式、候选数组）都是实例状态，所以没有什么需要重置，也没有什么被共享。
2. **字典不可变。** 过滤产生一个新的 `int[]` 下标数组。旧实现那个共享的 `CopyOnWriteArrayList`
   —— 过滤时被修改、每局重建 80 次 —— 在这里不可能存在。
3. **规则来自服务器。** `numberOfWordsToGuess` 和 `numberOfGuessAllowedForEachWord` 从
   `StartGame` 读取；`80` 和 `10` 在引擎里一处都不出现。
4. **重试的调用是安全的。** `SimulatedServer` 在改变状态之前注入故障，所以传输层的失败永远不会把
   同一次猜测计两遍。

### 一致性规则

一个候选词存活，当且仅当对每个位置 `i`：

- 如果 `i` 已揭示，候选词在该位置的字母等于揭示的字母；
- 如果 `i` 被遮蔽，候选词在该位置的字母**从未被猜过**。

第二句同时包含了两件旧代码分开追踪、且只应用到最近一次观测的事实：“词里不含任何我们猜错的字母”
和“揭示的字母恰好出现掩码显示的那几次”。因为一次命中会揭示该字母的所有出现位置，一个被猜过的字母
不可能藏在被遮蔽的位置上。

数据布局：词缓存为 `String[]`，一个平行的 26 位掩码 `int[]`，一个按累积下标构造的权重 `int[]`，
以及一个一次性建好的 `Map<Integer, int[]>` 长度桶。一次过滤是对基本类型的 O(candidates × length)
扫描，最多一次分配，什么都没淘汰时一次也不分配。

### 字母选择

`FrequencyLetterSelector` 在幸存候选上给每个未猜字母打分并取最大，平手按静态英语词频决定。两种
模式：

- `COVERAGE`（默认）—— **含有**该字母的候选词权重之和。直接估计 P(hit)，而分数奖励的正是这个。
- `OCCURRENCES` —— 权重乘以出现次数之和，旧实现的行为。它高估了在一个词里重复出现的字母，因为
  一次命中会揭示所有出现位置。

候选集为空（答案不在我们的字典里）时退化为纯词频顺序，而不是失败。

`InformationGainLetterSelector` 用 `log2(candidates)` 的期望下降量取代这个目标，保留下来作为被测量
的反例：529.50 对 1404.65。分数每回合变化 `21p - 1`，对 `p` 单调，所以任何以一次失手为代价的探索
永远不值得付钱；选择器自己的算术就偏好五五开的字母（1.0 bit）胜过 90% 的命中（0.469 bit），比例
是二比一。只有当试探免费时，熵才是正确的目标。

### 放弃一个词

每回合开始前问一次 `Solver.shouldAbandon()`。`GameEngine` 是唯一对它做出反应的地方，默认答案永远
是“不”，所以基线分毫未动。`SkipPolicy` 提供两条已实现的规则：`hopeless`（没有任何字典词能解释
证据）和 `expectedValue`（`20·P(solve) < (1−P)·missesLeft`，其中 `P` 来自负二项尾）。

两条都测过，默认都关闭。直觉上的第三条规则 —— 当隐藏字母的揭示成本超过剩余失手次数时放弃 —— 是
错的，而且代价昂贵，因为命中不消耗失手次数：它在长词档触发了 2.8%，全是能确定解出的词，代价是
−13 分。整个想法的先知上界是十分：只有 201 个把失手次数用完的第一档词可以被改善，每个最多改善它
尚未花掉的失手次数。

### 传输

`HttpHangmanClient` 通过 `java.net.http` 说文档描述的单端点协议，从响应里读取
`numberOfWordsToGuess` 和 `numberOfGuessAllowedForEachWord`，而不是假设 80 和 10。它有意不重试：
`RetryingHangmanClient` 包住它，这样策略可以在没有 socket 的情况下被测试。`Json` 是包私有的，
它存在是因为这里离线唯一能拿到的 JSON 库是 2018 年的；协议用到六种字段类型，嵌套不超过一层对象。

### 不假装地向前看

在信念状态上做规划是显而易见的下一步，而它放不下。一次失手不会缩小候选集，它只是花掉一个字母，
所以可达状态按“从一个词不用的字母里挑 k 个”的方式增长：`C(15, k)` 累加到 `k = 10` 约为每个决策
2^15 个状态，每个要算 26 次字母评估。截断搜索比跳过更糟：一个只给接下来几回合定价的叶子，配上
整个词的量纲，会系统性地偏好大揭示 —— 正是输掉 875 分的方向。所以这个里程碑选择测量。

`ExactScore` 把一个决策完整求解出来，没有启发式叶子，所以它的答案是真实期望。状态是（候选集，
已猜掩码，剩余失手），而模式是隐式的：位置 `i` 被揭示，当且仅当所有候选词在那里一致、且该字母已被
猜过 —— 这是把 `EliminationSolver` 的一致性规则反过来读，所以两者不可能漂移。`AuditedLetterSelector`
包住 `coverage`，问 `ExactScore` 最好的字母值多少、选中的字母值多少，记录差值，然后原样打出选中的
字母。因此被审计的一局得分与普通一局逐位相同；只有 `AuditSummary` 不同。这就是为什么那个数字可以
被当作测量而不是赌注来读，也是为什么审计可以在主配置上跑而不污染它。

### 给每一次猜测定价

审计定价了 1.6% 的决策。其余无法精确求解，所以第二个探针问了另一个问题：不是“有没有更好的字母”，
而是“选中字母产生的失手，是模型预言的那些吗”。

`MissAnatomy` 包住 `EliminationSolver` 并转发每一次调用，所以被插桩的一局得分与普通一局逐位相同
—— 100 局下 1404.65 对 1404.65，11.8 s 对 10.8 s。`nextGuess()` 快照候选数、剩余失手，以及委托者
自己给即将打出的字母算的 `P(hit)`；`observe()` 把 `wrongGuessCountOfCurrentWord` 与猜测前的值比较，
这能在一种击败“按候选集缩小推断”的情形下也区分命中与失手 —— 命中一个所有候选词都含有的字母，候选
集纹丝不动。

探针需要候选数组，而那正是求解器已经持有的，所以 `EliminationSolver` 增加了一个包私有的诊断访问器，
而不是第二份一致性规则的实现。公开接口什么都没变，`GuessContext` 也仍然没有模式字段。

`MissAnatomySummary` 累积三个分组 —— 按词长、按猜测序号、按 `P(hit)` 十分位 —— 每个都在
`1 - mean(P(hit))` 旁边报告实际失手率。第三个才可能出错：字母、它们的 `P(hit)`、以及模拟器的抽样
全都来自同一个 `RankWordWeighting`，所以一个校准过的探针必须显示实际比率逐行跟上预测，而跟不上的
一行就指明一个真实缺陷。

## 数据管线

`tools/fetch-data.sh` 下载 `david47k/top-english-wordlists/top_english_words_lower_100000.txt`
（Google ngram 词频 1950-2012，CC BY 3.0），保留 `^[a-z]{3,20}$`，去重，转大写，gzip 成
`src/main/resources/word-ranks.txt.gz`：

- 输入 100,000 行，输出 96,886 个词，395 KB；
- 按长度的档位容量：22,421 / 40,527 / 28,949 / 4,989。

两份词表，两种职责：

| 词表 | 规模 | 职责 |
|---|---:|---|
| 排名表（`word-ranks.txt.gz`） | 96,886 | 答案抽样权重；求解器的默认先验 |
| 字典（`../words.txt`） | 416,264 | 候选集 —— 服务器可能认识的所有词 |

实测重合度：82.5% 的排名词出现在 `words.txt` 里。剩下 17.5% 被排除在答案池之外，因为出一道字典
不可能包含的词，测量的是语料覆盖度而不是求解器质量。每份报告里都保留 `blind` 列，作为这次排除
确实发生了的检查。

权重按 `scale / rank^exponent` 衰减，`exponent = 0.5`、`scale = 1e6`、下限 1。纯 Zipf 的指数
1.0 会让最靠前的几个词吞掉整个分布；0.0 则塌陷到均匀。

## 模拟模型

`SimulatedServer` 在进程内实现 `HangmanClient`。保真度的取舍：

- 一次命中揭示所有出现位置，与文档一致；
- 答案按档位加权抽取（`--sampling uniform` 是悲观情形）；
- 档位遵循文档描述的按词序号划分的范围；
- 重复猜一个错的字母会再消耗一次失手，符合一个对对话没有记忆的服务器；
- 故障在任何状态变更之前以 `--failure-rate` 的概率注入。

三处含糊是被做成旋钮的，而不是被假设掉的：

| 含糊之处 | 两种读法 | 为什么重要 |
|---|---|---|
| 档位边界 | `CUMULATIVE`（`<=5`、`<=8`、`<=12`、`>12`）对 `BUCKETED`（3-5、6-8、9-12、13+） | 由对照组裁定：服务器用的是桶 |
| 答案分布 | `WEIGHTED` 对 `UNIFORM` | 约值 90 分 |
| 池子大小 | 排名表的前 N 个 | N=1k 到 N=100k 之间约值 120 分 |

## 评测协议

- 每个变体 `--games 100` 局、`--words 80`、`--seed 42`。二十局够看见 100 分的效果，但看不见
  10 分的，而指数平台恰好落在后一个量级里。
- 每一局用自己的种子 `seed + i * 1_000_003` 派生，所以第 *i* 局与这次跑包含多少局无关 —— 单独
  一局坏掉也能单独复现。
- Best-of-N 按另一种顺序复用这个布局：第 *g* 局的第 *a* 次尝试用
  `seed + (g + a * games) * 1_000_003`，所以每局第一次尝试正好是普通运行会打的那一局。因此
  best-of-N 逐局可证不劣于 best-of-1，而每一局本身仍然可以单独复现。
- 报告：均值、中位数、样本标准差、最小、最大，加上解出率、每词失手数、每词猜测数和字典未命中率，
  总体与分档各一份。
- 比较方式：只动一个旋钮，固定种子，报告相对分布离散度的差值。比标准差还小的差别不是结果。
- 前瞻审计增加了第二种证据：一个精确的期望分数，由对足够小以至于能算完的状态做值迭代得出，与
  实际打出的字母比较。它不需要种子纪律，因为它不是抽样；它的限制是覆盖度而不是噪声，而 CLI 会把
  定价了多少个决策、跳过了多少个都打印出来。
- 逐次探针增加了第三种证据：对每一个决策做校准检查，而不是从中抽样。它同样不需要种子纪律，
  但它拿模型对照它自己，所以只能发现内部不一致的模型，永远发现不了一个一致地对世界判断错误的
  模型 —— 如果权重和抽样同样偏了，它会看到完美吻合。

## 实测基线

种子 42，100 局 × 80 词，加权抽样，bucketed 档位：

| 变体 | 均值 | 标准差 | 解出率 | 失手/词 |
|---|---:|---:|---:|---:|
| coverage，语料先验（默认） | 1404.65 | 34.75 | 97.5% | 1.94 |
| occurrences，语料先验 | 1401.07 | 38.41 | 97.4% | 1.96 |
| coverage，均匀先验 | 1286.04 | 51.70 | 94.1% | 2.75 |
| occurrences，均匀先验 | 1281.28 | 50.88 | 94.1% | 2.80 |

三个发现驱动着余下的路线图：

1. **先验约值 119 分**，超过目前测到的任何其他项。
2. **第一档吃掉了大部分损失**（有先验时每词 4.63 次失手，没有时 6.48，而最后一档是 0.20；四档
   平均 1.94，所以这一档占全部失手的 60%）。任何后续工作都应该瞄准候选集很大的短词。
3. **先验的强度不值得调。** 每个点 100 局：0 → 1286.04，0.25 → 1396.72，0.5 → 1404.65，
   0.75 → 1401.62，1.0 → 1395.29。从 0.25 到 1.0 全都落在平台的三个标准误之内；只有“用不用它”
   才是要紧的。

池子大小，每格 100 局，coverage，语料 / 均匀：1,000 → 1511.47 / 1279.23，5,000 → 1498.22 /
1297.46，20,000 → 1468.32 / 1286.65，100,000 → 1404.65 / 1286.04。语料那一列斜了 107 分，而
均匀那一列移动 18 分且没有趋势，这比 M1 能说的更锋利：池子只对读取语料的求解器是难度。没有排名
信号的求解器，无论哪些词合格，都会用同样的方式选字母。

在 cumulative 档位下，均匀那一列**确实**斜了（1023.59 → 1150.60）。档位读法移除了产生它的那
条路径 —— 一个短答案落进一个候选集横跨字典整个短端的档位 —— 也移除了那个效应。

### 对照组

`legacy/LegacySolver` 在同一个 `Solver` 接口背后重放原来的决策逻辑，所以 harness 能给它打分。
它存在有两个原因：给前面列出的缺陷定价，以及裁定 M1 一直当作硬币抛的那处档位含糊。

每格 100 局，种子 42，加权抽样：

| 难度读法 | coverage | legacy |
|---|---:|---:|
| bucketed | 1404.65（sd 34.75） | 1260.24（sd 50.30） |
| cumulative | 1322.29（sd 50.91） | 841.13（sd 92.42） |

已发布的客户端在一次真实对局中拿到过 1326。在桶读法下，它落在重放均值之上 1.31 个标准差 —— 一次
普通抽样。在 cumulative 下，它落在 5.25 个标准差之上。5σ 的差距不是一次坏对局，所以服务器用的
是互不重叠的桶：客户端的档位逻辑是在跟随服务器，而 `<=5` 那个措辞描述的是一个从未被玩过的游戏。

两个后果，其中一个撤回了一项早先的断言：

- 在真实存在过的世界里，重写值 **144 分**（1404.65 − 1260.24），在文档描述的世界里值 **481**。
  前者是诚实的头条。后者衡量的是：当答案的长度落在词序号所选桶之外时，这种错配变得多具破坏性
  —— `blind` 率从 0.0% 变成第二档的 38.7% 和第三档的 70.0%。
- M1 说 1329 “复现”了 1326，那是巧合，不是验证。它拿 cumulative 档位下的 `coverage` 去比
  buckets 下的 `legacy` —— 两个程序，两个不同的游戏。撤回。真实的是那个更弱的断言：legacy
  重放自己的分布以 1.31σ 包含 1326。

差距不是均匀分布的：144 分里约 107 分在第一档。在桶读法下候选集本身就是对的 —— 服务器只问它指名
的桶里的词，所以 legacy 的过滤永远不会丢掉答案 —— 而客户端缺的是给那个集合**排序**的能力。它给
字母排名，不给词排名，而在第一档一万六千个候选词上，那就是 73.5% 和 90.0% 解出率的区别。

## 里程碑

- **M1** —— 模拟器、字典、求解器、引擎、CLI、报告、测试。完成。
- **M2** —— 语料先验成为默认，`--exponent` 旋钮，已测量。完成：扫描显示这个决定是二值的（用不用
  语料先验），而指数平台从 0.25 到 1.0 是平的。
- **M3** —— 放弃策略。完成，带一个负面结果：`hopeless` 和 `expectedValue` 在 8,000 个词上都触发
  零次，直觉的“剩余失手不够”规则损失 13 分，而整个想法的先知上界是十。留在 `--variants` 后面，
  默认关闭。
- **M4** —— 基于 `java.net.http` 的 `HttpHangmanClient`，配手写 JSON 编解码（不用 Jackson），
  以及 best-of-N 的对局选择。完成：N = 2 / 4 / 8 / 16 时 +20.4 / +36.3 / +48.4 / +56.0 分，
  对应 `σ·e_N` 预测的 +19.6 / +35.8 / +49.5 / +61.4。同一局的多次尝试并发跑，所以 N = 4 比
  N = 1 只多花 11% 的墙上时间。
- **M5** —— 精确前瞻审计，M3 那个悬而未决问题的答案。完成，而且很小：被定价的决策里有 9% 到 21%
  不是最优，但整个审计每局只值 1.26 到 3.14 分，因为每个差距 0.12 分。它定价了全部选择的 1.6%
  到 3.7%；中局既不被这个数字触及，也不被这个里程碑触及。
- **M6** —— 对每一次猜测做校准探针，补上 M5 留下的洞。完成，带一个负面结果：70,788 次猜测里有
  49.2% 是必然命中，只贡献 0.9% 的失手，而剩下的一半以 42.7% 失手，预测是 43%。逐行看，除了一
  行 53 个决策的之外，最大偏差是一个标准误。没有错价要修。
- **C**（插在 M2 和 M3 之间）—— 旧算法重放为对照组。完成：它重读了 M1 的头条，给缺陷表定价
  144 分，并把档位含糊裁定为桶。

### Best of N

每行 100 局，`coverage`，种子 42：

| 每局跑几次 | 均值 | 标准差 | 最小 | 最大 | 墙上时间 |
|---:|---:|---:|---:|---:|---:|
| 1 | 1404.65 | 34.75 | 1316 | 1474 | 11.4 s |
| 2 | 1425.02 | 27.58 | 1324 | 1478 | 11.4 s |
| 4 | 1440.96 | 19.09 | 1391 | 1482 | 12.6 s |
| 8 | 1453.04 | 16.13 | 1413 | 1484 | 24.1 s |
| 16 | 1460.66 | 11.49 | 1430 | 1485 | 49.8 s |

机制是被理解了的，不只是被观察到：N 个抽样最大值的均值上升 `σ · e_N`，其中 `e_N` 是 N 个标准
正态最大值的期望。五个差值里有四个落在该预测的 1.5 分之内。这也是整个练习里最大的一笔单项收益，
而这恰恰是令人不安的发现 —— 比重写相对原版值的那 144 分还大，更远远大过最优放弃规则值的那十分。

### 前瞻审计

100 局，`coverage`，种子 42，每行是三个上限的一组设置：

| 候选 / 失手 / 状态 | 定价的决策 | 非最优 | 每局放弃的分 |
|---|---:|---:|---:|
| 40 / 3 / 5,000（默认） | 70,788 中的 1,121 | 13.8% | 1.26 |
| 40 / 3 / 20,000 | 70,788 中的 1,146 | 14.9% | 1.30 |
| 40 / 5 / 5,000 | 70,788 中的 2,015 | 9.1% | 1.39 |
| 80 / 3 / 5,000 | 70,788 中的 1,260 | 20.9% | 1.69 |
| 80 / 5 / 20,000 | 70,788 中的 2,617 | 18.7% | 3.14 |

两条读法，一条禁令。犯错很常见，也很便宜：最宽的一行是 100 局 2,617 个决策共 314 分，每个 0.12，
因为期望在几个合理字母之间几乎是平的 —— 只剩一次失手、三个候选词时，确定揭示和一个三分之一的
命中都值 20/3。把范围放宽 2.3 倍买到 1.9 分，墙上时间大约翻倍，所以结果不随覆盖度缩放。而且它
绝不能被读成前瞻的总价值：审计定价了 1.6% 到 3.7% 的选择，而它够不到的状态恰恰是最宽、最有犯错
空间的那些。它能确立的是：终局 —— 二十分摆动最大、词真正被救回或输掉的地方 —— 距离最优在 0.6%
到 1.6% 之内，而每局剩余差距是 195 分。

### 逐次猜测的探针

100 局，`coverage`，种子 42，70,788 次猜测和 15,495 次失手：

| 区间 | 猜测数 | 占比 | 失手数 | 失手占比 | 实际失手率 |
|---|---:|---:|---:|---:|---:|
| `P(hit)` 0.9 到 1.0 | 34,816 | 49.2% | 139 | 0.9% | 0.4% |
| `P(hit)` 低于 0.9 | 35,972 | 50.8% | 15,356 | 99.1% | 42.7% |
| 全部 | 70,788 | 100% | 15,495 | 100% | 21.9% |

模型整体预测 22.0%，在风险那一半上约 43%。三条读法：

1. **一半的猜测不可能消耗失手。** 70,788 次里有 34,816 次落在每个幸存候选词都含有的字母上，它们
   产生了 0.9% 的失手。所有出错的事都发生在另一半，而在那一半里，实际比率和预测重合。
2. **预测逐行成立。** 按 `P(hit)` 十行、按词长十八行、按猜测序号十行。最小行之外的最大偏差是
   0.011，出现在一行 7,453 个决策上，一个标准误；`0.0-0.1` 那行差 0.071，基于 53 个决策，它自身
   的标准误是 0.077。
3. **校准加上贪心，关闭了单步问题。** 单独看，吻合只说明模型知道自己的赔率 —— 一个选烂字母的
   求解器同样能校准得很好，只是比率更差。它之所以有决定性，是因为 `coverage` 每一步都在最大化
   同一个数，所以没有别的字母能在它被选中的那一刻降低期望失手数。

形状值得记下来，因为它解释了分数在哪。选中的字母在三字母答案上 28.6% 命中，在十三字母上 97.6%：
短词只有三个位置放一个字母，长词有十三个。在一个词内部，头两次猜测带着 31.5% 的失手率，第九次
是 14.4%；`10+` 处的上升是幸存者偏差，因为十回合后还在跑的词就是没解出来的词。

探针做不到的是给**序列**定价 —— 现在选差一点的字母换以后更好的赔率。那是审计在终局定价为 1.3 到
3.1 分、而 `information` 在极端情形定价为 −875 分的问题。中局仍然没有定价，但它不再无法解释：
那里的失手是模型预言过的。

## 决策与被否掉的替代方案

| 决策 | 理由 | 被否掉的 |
|---|---|---|
| 先做离线模拟器，HTTP 放最后 | 不可测量的求解器无法改进；一局必须只花几毫秒 | 先写 HTTP 客户端然后盲迭代 |
| 不可变字典 + 下标过滤 | 移除了让 legacy 跑 86 分钟的 O(n²) 变更 | 保留可变的候选列表 |
| 候选一致性只有一个条件 | 一条规则，而不是两套需要同步的结构 | `wrongHistory` 列表 + `rightGuess` 映射 |
| 每个动作一个类型化方法 | 每个动作恰好返回一种形状；一个 sealed 响应层次只会加一层没人需要的东西 | 带 `type` 判别器的泛型 `Response` |
| `Sleeper` 接口 | 退避曲线被精确断言，而模拟不必真的等 | 静态调用背后的真实 sleep |
| M1 就做 `RetryingHangmanClient` | 否则模拟器的故障注入就是没有测试的死代码 | 把重试推到 M4 |
| 档位做成配置旋钮 | 措辞容许两种读法，而对照组后来指出了服务器用哪一种 | 悄悄选 legacy 的读法 |
| 答案池 ∩ 字典 | 把求解器质量和语料覆盖度隔离开 | 从原始排名表抽答案 |
| `--exponent 0` 也把下限权重压平 | 旋钮必须有一个可验证的左端点；现在它逐字节复现 `--priors uniform` | 让未列出的词保持下限 1，使 0 变成第三种没人要求的信念 |
| CLI 里把 `truth` 和 `belief` 两个排名分开 | 一次先验扫描不能移动答案分布，否则结果无法归因 | 模拟器和求解器共用一个排名 |
| 提交 gzip 的排名表 | 构建保持离线；395 KB 很便宜 | 构建时下载 |
| 把旧算法在模块内重放为对照组 | 一个用分数定价的缺陷是论证；同一个缺陷用散文描述是意见，而且为了让它成立，值得把 harness 的 `Variant` 从“一个字母选择器”改写成“一个求解器工厂” | 改写一下缺陷清单然后继续 |
| 对照组证明之后把默认切到 `bucketed` | 默认应该描述真正被打过的那个游戏；把字面读法留作头条，会让每个已发布的数字都描述一个从未存在过的世界 | 保留 `cumulative` 以免重跑那些表 —— 代价是三分钟测量加一次诚实的改写 |
| 依据证据放弃，而不是依据失手算术 | 命中不消耗失手次数，所以“剩余失手不足以揭示字母”不是一个输势；它被实现、测量为 −13 分，然后被空候选集判定取代 | 因为那条规则看起来免费就留着它 |
| 放弃策略默认关闭 | 两条可实现的规则在 8,000 个词上都触发零次；一个从不改变行为却每回合加一次检查的默认值是负债 | 因为做了就打开 |
| 手写 `Json` 而不用 Jackson | 零运行时依赖让 `mvn -o` 继续可用；协议有六种字段类型和一层嵌套 | 加 Jackson 2.9，这里离线唯一能拿到的版本 |
| `HttpHangmanClient` 不重试 | 只有可分离时重试策略才可测，否则调用次数不可见 | 在客户端内部重试，那样每个协议测试都需要一个 socket |
| best-of-N 的种子布局 `g + a * games` | 每局的第 0 次尝试就是普通运行的那一局，所以 best-of-N 逐局可证不劣，而每一局本身仍然可复现 | `g * attempts + a`，它让每组的第一次尝试都是新的，破坏了比较 |
| harness 里并发跑尝试 | 它们除不可变状态外不共享任何东西；八局只花一局的墙上时间，这才让 1,600 局的测量可行 | 顺序跑，付八倍墙上时间 |
| 模式从候选重建，而不是存储 | `GuessContext` 没有模式字段也不需要：位置 `i` 被揭示，当且仅当所有候选在那里一致且字母已知，也就是一致性规则反过来读 | 给公开的 selector 契约加一个模式字段，好让审计读到它 |
| 审计永远打被包装者的字母 | 改变被测量对象的测量，是一个带两个变量的实验；这样被审计的一局的分数在构造上就是相同的，而差距是一个数而不是一个带噪声的差值 | 让审计返回最优字母然后测分数差 —— 那个差值会被 ±35 分的离散度淹没 |
| 超预算的决策被拒绝，而不是截断 | 截断的递归用整个词的量纲给最后几回合定价，会系统性地偏好大揭示 —— 那个 875 分的错误 | 限制深度并接受一个有偏的答案 |
| 三个审计上限是 CLI 开关 | README 声称审计覆盖 1.6% 的选择；读者必须能放宽它并看着数字变化，否则这个声称无法被审计 | 把上限写死，报告一行 |
| 探针包住求解器，而不是选择器 | 命中或失手的答案只存在于求解器层，而转发每一次调用才是让插桩运行分数相同的原因 | 从候选集缩小推断命中 —— 命中一个所有候选都含的字母会让集合不变 |
| 一个包私有的候选访问器 | 探针住在 `solver` 里，需要求解器已经持有的数组；每次猜测拷一份会是探针唯一新增的成本 | 从证据重建候选集，重复一致性规则 |
| `P(hit)` 只给一个字母定价，而不是二十六个 | 探针每次猜测跑一次，候选最多 1.6 万；选择器的完整遍历会是一个数字的 26 倍工作量 | 复用选择器的累加结果然后取一格 |
| delta 对各自的噪声读，而不是合并 | 一行十个决策可以摆动 0.3；公布每行的规模和它的标准误，才是让校准声称保持可证伪的东西 | 报一个总偏差然后说吻合 |

## 风险

- 答案分布无法验证。缓解：敏感性表，与每个头条数字一起报告。
- 排名表里有 17.5% 不在 `words.txt` 中，所以有效答案池比排名表暗示的要窄。缓解：在 CLI 表头里
  报告，并且 `blind` 留在每份报告里。
- 贪心求解器在宽候选集上把价值留在了桌上。部分缓解：信息增益的替代方案被构建并测量了（−875），
  所以“贪心是错的”不再是一个未经检验的直觉；终局被精确定价为 1.3 到 3.1 分；逐次探针显示每一次
  失手都按模型分配的概率到达，所以单步选择没有错价。仍然未被检验的是中局 —— 一千个候选词，大部分
  失手还在手里 —— 审计的状态空间在那里放不下。一个被校准的贪心步骤在那里排除了一个错误的**字母**；
  它没有排除一个更差的**序列**。
- Best-of-N 依赖于说明里从未写出的一条规则：多次提交中哪一次算数。缓解：CLI 在每次 best-of 运行时
  都会说明，README 会写明每一行假设的是哪种读法。
- 一个没有 `--pool` 的分数，对任何读取语料的求解器都无意义：池子在扫描中让那个求解器移动 107 分，
  而无先验的求解器移动 18 分。缓解：每份报告的表头都打印它，扫描在 README 里。
- 档位读法依赖于一次历史对局加一次重放，而不是服务器源码。缓解：它产生的差距是 5σ，而
  `--difficulty` 让两种读法都可运行，所以较弱的那个可以被直接检查。
- legacy 重放会跳过已经猜过的字母，而原版可能重复猜一个。这只会抬高 legacy 的分数，让每个报告的
  差距成为下界。缓解：不需要 —— 方向已知且保守。
